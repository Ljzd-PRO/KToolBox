    命名形式¶

    KToolBox v1 の命名設定はプロジェクト単位です。CLI と WebUI は ktoolbox.toml の同じ [naming] を使用し、命名項目はグローバル dotenv 設定では編集しません。

    ディレクトリ構造を設定する¶

    WebUI の**命名形式**では、次を設定できます。

    • 作者、作品、リビジョン、年、月のディレクトリテンプレート
    • メインファイル（カバー）と添付ファイルのテンプレート
    • 作品内の添付、リビジョン、本文、外部リンク名
    • 年月グループ、作品ファイルの混在、添付の連番

    Pawchive は判読しにくいストレージ名を返すことが多いため、添付ファイルの連番命名は既定で有効です。元のファイル名に意味があり、保持したい場合にのみ無効にしてください。

    テンプレートでは、欄の横に表示される {creator_name}、{creator_id}、{service}、{title}、{post_id}、{revision_id}、{year}、{month} などの変数だけを使用できます。パス区切り、親移動、未知の変数、安全でない名前はスキャン前に拒否されます。

    **ディレクトリ構造**と**命名テンプレート**には個別の保存ボタンがあります。保存内容は今後のダウンロードへ直ちに反映されますが、既存ファイルが自動的に移動することはありません。

    **既定のダウンロード先**もプロジェクト設定です。既定値は downloads で、相対パスはプロジェクトルート基準、絶対パスはプロジェクト外も指定できます。タスクの明示出力、 自動同期プランの明示出力、プロジェクト既定値の順で使用します。作成時に解決した絶対パスを固定するため、後から既定値を変更しても既存タスクは移動しません。

    作品ディレクトリに添付ファイルを保存する¶

    「ディレクトリ構造」で添付ファイルのディレクトリを . または ./ にすると、カバーやメタデータと同じ場所に保存できます。この例外は添付ディレクトリだけに適用され、本文、外部リンク、リビジョンのパスには引き続き名前が必要です。

    次の v0 設定で保存したファイルは「旧ダウンロード変換 → 設定を貼り付け」から変換できます。

    KTOOLBOX_JOB__POST_STRUCTURE__ATTACHMENTS=./

    省略した ENV 項目には v0 の既定値が使われるため、v0 で変更した他の命名設定も貼り付けてください。変換先は常に現在のプロジェクト形式です。確定前にプレビューを確認してください。post.json またはクリエイター索引で識別できる添付ファイルを、リビジョン内も含めて個別に移動します。カバーやメタデータを添付ファイルとして移動せず、識別できないファイルは作品ディレクトリ内の相対位置を維持します。既存の移動先ファイルや危険なパスがある場合は変換を止め、上書きしません。

    以前のダウンロード場所を変換する¶

    保存済み形式へ既存内容を合わせる場合だけ、独立した**以前のダウンロード変換**タブを開きます。以前の場所を追加してスキャンしてください。ここで指定する場所は変換元であり、今後のタスクの保存先ではありません。

    変換ツールはいつでも利用でき、変換元を 2 つの方法で指定できます。**プロジェクト履歴**では保存済みの命名バージョンを複数選択でき、同じ保存先に複数世代の構成が混在している場合にも対応します。**設定を貼り付け**では、旧 .env の命名キー、完全な ktoolbox.toml、[naming] テーブル、見出しのない命名断片を解析できます。ハイライト付きエディターは例とフィールド単位のエラーを表示し、貼り付けた原文はメモリ内だけで解析され、ブラウザーストレージ、ログ、イベント、変換履歴には保存されません。どちらの方法でも現在のプロジェクト命名バージョンが読み取り専用の変換先となり、プロジェクト設定を上書きしません。

    保存済みの各レイアウトには、その時点の公開日時ポリシーも固定されます。修正前のプロジェクト版は「Pawchive の値をそのまま使用」と表示されます。貼り付けた v0 .env は既定で「Kemono UTC」、TOML は Kemono UTC、Pawchive 原値、または独自の Service タイムゾーンを選択できます。たとえば Fanbox の 2025-12-21T00:35:43 は Asia/Tokyo として解釈され、UTC の変換先では 2025-12-20T15:35:43+00:00 になるため、{published} のパスは 2025-12-21 から 2025-12-20 へ移動します。post.json の Pawchive 原値は変更しません。

    スキャンはファイルシステムを直接読み取り、タスク履歴だけに依存せず、Pawchive にも接続しません。作者ディレクトリの識別情報、creator-indices.ktoolbox、post.json を使い、選択場所の外へ出るシンボリックリンクはたどりません。

    プレビューには作者ごとの新旧パス、作品数、ファイル数、合計サイズ、スキップ、競合が表示されます。安全に変換できる作者はすべて既定で選択されます。

    KToolBox は対象を上書きまたは統合しません。古いプレビュー、設定変更、関連する実行中タスク、重複対象、ファイルシステム変更がある場合は再スキャンが必要です。

    変換と復旧¶

    KToolBox は選択した移動を永続バックグラウンド処理として実行します。**一時停止**は現在の原子的ファイル操作の完了を待って状態を保持し、**再開**前に設定、ファイル指紋、競合、空き容量を再検証します。**取消**は別の操作で、完了済み移動を逆順に戻します。書き込み失敗やプロセス中断でも安全にロールバックします。

    進捗と履歴は .ktoolbox/webui.sqlite3 に保存されます。成功時は一時操作ログを削除し、履歴は手動削除まで保持します。空になった移動元ディレクトリは削除しますが、無関係なファイルは削除しません。

    初回起動時の移行¶

    .env または prod.env に旧命名キーが見つかった場合だけ移行ウィザードを表示します。起動時は検出と端末警告だけを行い、ファイルは変更しません。ログイン後のウィザードでは次を行います。

    1. 出所、旧値、現在のプロジェクト値を表示
    2. 旧値を既定選択し、項目ごとに現在値を残せるようにする
    3. プロジェクト設定と dotenv の変更を正確にプレビュー
    4. 確認後に .ktoolbox/migrations/project-naming-v2/ へバックアップし、ktoolbox.toml の書き込みと旧キー削除を原子的に実行
    5. 設定移行後、別工程として旧ディレクトリ変換を案内

    閉じる、または**無視**を選んでも、その表示だけを閉じます。旧キーが残る限り、再読み込みや再ログインで再表示されます。設定移行とディレクトリ変換は別工程です。旧場所を確認してから明示的にスキャンを実行し、ツールを開いただけではスキャンも移動も始まりません。

    CLI もプロジェクト命名設定を使用します。旧プロジェクトでは WebUI でバックアップ付きの原子的移行を確認してください。プロセス環境にだけ存在する旧値は削除できないため、KToolBox は命名には使わず、起動環境から削除されるまで警告します。
