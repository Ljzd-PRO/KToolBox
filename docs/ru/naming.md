# Формат имён

В KToolBox v1 формат имён задаётся для проекта. CLI и WebUI читают одну секцию `[naming]` из `ktoolbox.toml`; эти поля больше не редактируются как глобальные dotenv-настройки.

## Настройка структуры

На странице **Формат имён** можно задать:

- шаблоны каталогов автора, работы, редакции, года и месяца;
- шаблоны основного файла (обложки) и вложений;
- внутренние имена вложений, редакций, содержимого и внешних ссылок;
- группировку по годам/месяцам, смешивание работ и последовательные имена вложений.

Последовательная нумерация вложений включена по умолчанию, поскольку Pawchive часто возвращает нечитаемые имена хранилища. Отключайте её только тогда, когда исходные имена содержательны и их необходимо сохранить.

Допустимы только показанные рядом переменные, например `{creator_name}`, `{creator_id}`, `{service}`, `{title}`, `{post_id}`, `{revision_id}`, `{year}` и `{month}`. Разделители пути, переходы к родителю, неизвестные переменные и небезопасные имена отклоняются до сканирования.

Для **структуры каталогов** и **шаблонов имён** предусмотрены отдельные кнопки сохранения. Сохранение сразу применяется к будущим загрузкам, но никогда само по себе не перемещает старые файлы.

**Каталог загрузки по умолчанию** также относится к проекту. Начальное значение — `downloads`: относительный путь считается от корня проекта, а абсолютный может находиться вне проекта. Приоритет: явный путь задачи, явный путь плана автосинхронизации, затем значение проекта. В созданной задаче фиксируется разрешённый абсолютный путь.

## Вложения в каталоге произведения

В разделе **Структура каталогов** укажите `.` или `./` для каталога вложений, чтобы сохранять их рядом с обложкой и метаданными. Это исключение действует только для вложений: пути текста, внешних ссылок и ревизий по-прежнему должны иметь имя.

Файлы, загруженные с такой настройкой v0, поддерживаются в разделе **Преобразование старых загрузок > Вставить конфигурацию**:

```dotenv
KTOOLBOX_JOB__POST_STRUCTURE__ATTACHMENTS=./
```

Добавьте остальные настройки именования, изменённые в v0: для пропущенных полей ENV используются значения v0 по умолчанию. Целью всегда остаётся текущий формат проекта. Перед подтверждением проверьте предпросмотр: вложения, определённые по `post.json` или индексу автора, перемещаются по одному, в том числе в распознанных ревизиях. Обложки и метаданные не считаются вложениями, а неопознанные файлы сохраняют своё относительное положение внутри каталога произведения. Существующий целевой файл или небезопасный путь блокирует преобразование без перезаписи.

## Преобразование прежних расположений

Открывайте отдельную вкладку **Преобразование старых загрузок**, только если существующие данные должны соответствовать сохранённому формату. Добавьте прежние расположения и запустите сканирование. Эти пути являются источниками преобразования, а не местами сохранения будущих задач.

Преобразователь доступен в любое время и поддерживает два вида источника. **История проекта** позволяет выбрать несколько сохранённых версий имён, если в одном расположении смешаны структуры разных поколений. **Вставить конфигурацию** принимает старые ключи `.env`, полный `ktoolbox.toml`, таблицу `[naming]` или фрагмент без заголовка. Редактор с подсветкой содержит примеры и отмечает ошибки отдельных полей; вставленный исходный текст разбирается только в памяти и не сохраняется в браузере, журналах, событиях или истории. В обоих режимах текущая версия проекта остаётся целью только для чтения и никогда не перезаписывается.

Каждая сохранённая схема также фиксирует действовавшую политику времени публикации. Версии до исправления отмечаются как «Исходное значение Pawchive». Вставленный `.env` v0 по умолчанию использует «Kemono UTC», а для TOML можно выбрать Kemono UTC, исходное значение Pawchive или собственные пояса Service. Например, Fanbox `2025-12-21T00:35:43` интерпретируется в `Asia/Tokyo` и для цели UTC становится `2025-12-20T15:35:43+00:00`, поэтому путь `{published}` меняется с `2025-12-21` на `2025-12-20`. Исходное значение Pawchive в `post.json` сохраняется.

Сканирование читает файловую систему напрямую, не полагается только на историю задач и не обращается к Pawchive. Содержимое определяется по каталогу автора, `creator-indices.ktoolbox` и `post.json`; символические ссылки за пределы выбранных расположений не открываются.

Предпросмотр показывает старый и новый путь, число работ и файлов, размер, пропуски и конфликты для каждого автора. Все безопасно преобразуемые авторы выбраны по умолчанию.

![Мобильный предпросмотр преобразования](../assets/webui/38-naming-conversion-mobile-dark.png)

KToolBox не перезаписывает и не объединяет цель. Устаревший просмотр, изменённая конфигурация, связанная активная задача, дублирующаяся цель или изменение файловой системы требуют нового сканирования.

## Преобразование и восстановление

KToolBox выполняет перемещения как постоянную фоновую операцию. **Пауза** ждёт завершения текущей атомарной файловой операции и сохраняет уже выполненные шаги. Перед **продолжением** повторно проверяются конфигурация, отпечаток файловой системы, конфликты и свободное место. **Отмена** возвращает выполненные перемещения в обратном порядке. Ошибка записи или прерывание также запускают безопасный откат.

Прогресс и история хранятся в `.ktoolbox/webui.sqlite3`. После успеха временный журнал удаляется, а история остаётся до ручного удаления. Пустые исходные каталоги удаляются, но посторонние файлы никогда не затрагиваются.

## Миграция при первом запуске

Мастер отображается только при обнаружении старых ключей имён в `.env` или `prod.env`. При запуске выполняются только обнаружение и предупреждение в терминале, без изменения файлов. После входа мастер:

1. показывает источник, старое и текущее значение проекта;
2. по умолчанию выбирает старые значения, позволяя оставить отдельные текущие;
3. предварительно показывает изменения проекта и удаляемые dotenv-ключи;
4. после подтверждения создаёт копии в `.ktoolbox/migrations/project-naming-v2/`, атомарно записывает `ktoolbox.toml` и удаляет старые ключи;
5. затем отдельно предлагает преобразование прежних каталогов.

![Мастер переноса старых настроек имён](../assets/webui/39-naming-migration-desktop-light.png)

Закрытие или **Игнорировать** скрывает только текущий диалог. Пока старые ключи существуют, он появится снова после обновления или нового входа. Миграция конфигурации и преобразование каталогов разделены: сначала проверьте прежние расположения, затем явно запустите сканирование. Одно открытие инструмента не запускает сканирование или перемещение.

CLI также использует настройки проекта. Для старого проекта подтвердите в WebUI атомарную миграцию с резервной копией. Старые значения только из окружения процесса нельзя удалить автоматически: KToolBox игнорирует их для имён и предупреждает до удаления из среды запуска.
