# WebUI 프로젝트 작업 흐름

WebUI를 설치하고 프로젝트에 연결한 뒤 이 페이지에서 프로젝트 데이터와 설정을 관리합니다. 작업 실행 및 배포 정보는 별도의 가이드로 나뉩니다.

## 프로젝트 워크플로

인터페이스는 처음 사용할 때 브라우저 언어를 따르고 중국어 간체, 중국어 번체, 영어, 일본어, 한국어, 프랑스어 또는 러시아어 선택을 유지합니다. 언어를 바꾸면 React Aria 날짜, 숫자 형식, 자연 정렬, 설정 메타데이터, 입력 검증 및 알려진 서버 오류도 함께 갱신됩니다. 라이트 또는 다크 모드를 선택할 때까지 운영 체제 테마를 따릅니다. 파란색, 에메랄드, 보라색, 장미색, 호박색 강조 팔레트를 사용할 수 있으며 활성화된 양식 스위치는 팔레트 간 상태 일관성을 위해 파란색을 유지합니다. 데스크톱은 간결한 사이드바, 좁은 화면은 Drawer를 사용합니다.

![7개 언어 선택기](../../assets/webui/23-language-menu-seven-locales.png)

![라이트 설정 편집기](../../assets/webui/09-configuration-light.png)

편집 영역은 구분되는 필드 배경이 있는 차분한 보조 표면을 사용합니다. 필드 아이콘은 탐색을 돕고 스위치와 체크박스는 중앙 작업 버튼처럼 보이지 않도록 레이블과 왼쪽 정렬됩니다. 스위치는 꺼짐일 때 회색, 켜짐일 때 파란색이며 체크박스는 선택되거나 불확정일 때만 표시됩니다. 편집 모달 내용과 고정 작업 표시줄은 하나의 연속 표면을 공유합니다.

주요 영역:

- **개요:** 프로젝트 경로, 큐 상태, 활성 전송 합계 및 최근 작업.
- **작업:** 동기화 또는 단일 작품 다운로드 생성, 편집, 일시 중지, 재개, 중지, 재실행, 삭제 및 조회. 읽기 쉬운 대상 링크만 세부 정보를 열며 작업 버튼은 탐색을 유발하지 않습니다. 여러 항목을 선택해 가능한 일괄 작업도 실행할 수 있습니다.
- **자동 동기화:** 여러 정기 작가 동기화 계획을 만들고 최근 업데이트 수와 실행 기록을 확인하며 계획을 일시 중지하거나 즉시 실행합니다.
- **크리에이터:** Pawchive 검색과 목록 항목 추가, 메모 편집, 활성화, 비활성화, 삭제. 일괄 활성화, 비활성화 및 삭제도 지원합니다.
- **게시물:** 작품 검색, 개정판 조회 및 다운로드 작업 생성. 이미지 미리보기는 NSFW 모드를 명시적으로 켠 경우에만 표시되며 본문은 기본적으로 접힙니다.
- **제외 규칙:** `field-match` 순서와 범위, 중첩 `any`/`all`, 포함, 같음, 정규식 및 존재 조건 구성.
- **전역 설정:** 형식 지정 양식 또는 고급 텍스트 보기로 `.env`, `prod.env`, `ktoolbox.toml` 편집.
- **시스템:** 프로젝트와 애플리케이션 버전 조회 및 예제 환경 파일 다운로드.
- **정보:** KToolBox 버전, 라이선스, 실행 환경, 작성자, 문서, 저장소와 문제 보고 링크를 표시하며 작성자 이메일은 노출하지 않습니다.

![좁은 화면의 작업 편집기](../../assets/webui/19-task-form-mobile-light-zh.png)

![Pawchive 크리에이터 목록](../../assets/webui/41-creators-showcase-desktop-light.png)

작업 생성은 오버플로 컨트롤 없이 두 개의 고정 탭을 사용합니다. 동기화 날짜는 공식 HeroUI의 단일 `year/month/day - year/month/day` 범위 필드로 유지되며, “시작일 없음”과 “종료일 없음”은 각 경계를 독립적으로 지웁니다. 게시물 오프셋은 50단위로 증가합니다. 제목 필터는 쉼표 또는 Enter로 생성하는 삭제 가능한 HeroUI Chip을 사용합니다. 단일 작품 다운로드와 목록에 크리에이터를 추가할 때는 독립 HeroUI 필드를 사용하고 `/platform/user/creator/post/post`과 같은 코드 스타일 Pawchive 경로 조각으로 구분합니다. 구분자는 입력 필드로 표현하지 않습니다.

데스크톱 행과 모바일 항목 모두 크리에이터 ID를 주 식별자로 표시합니다. 선택적 목록 메모는 별도로 표시되며 ID를 대신하지 않습니다. 기존 크리에이터를 편집할 때 플랫폼과 크리에이터 ID는 목록 항목을 식별하므로 표시되지만 읽기 전용입니다.

## 선택적 민감 미디어 미리보기

NSFW 모드는 새 브라우저에서 항상 꺼져 있습니다. 꺼진 동안 크리에이터와 작품 페이지는 텍스트만 표시하며 이미지 요청이나 빈 미디어 공간을 만들지 않습니다. 켤 때마다 확인이 필요하고, 켜진 상태는 사용자가 끌 때까지 현재 브라우저에 저장되어 탭 사이에 동기화됩니다.

브라우저는 인증된 동일 출처 WebUI 프록시를 통해서만 미디어를 가져오며 Pawchive 파일 호스트에 직접 연결하지 않습니다. 프록시는 비트맵을 완전히 디코딩해 검증하고 리디렉션, SVG, 비이미지, 손상 파일, 32 MiB 또는 50 MP를 넘는 리소스를 거부하며 제한된 썸네일을 생성합니다. 크리에이터 아바타와 배너, 작품 표지, 이미지 첨부 파일, 지원되는 본문 이미지를 표시할 수 있습니다. 갤러리는 한 번에 12개씩 불러오고 뷰어는 방향키와 Escape를 지원합니다. 비디오, 압축 파일 및 기타 첨부는 텍스트로 유지됩니다.

## 자동 동기화

**자동 동기화** 페이지는 여러 계획, 여러 작가 선택, 5필드 Cron, 그리고 최소 15분의 고정 기준 간격을 지원합니다. 각 계획에는 IANA 시간대, 첫 실행 경계, 출력 옵션과 다음 3회 실행 미리보기가 있습니다. 즉시 실행도 같은 작업 큐를 사용하며 성공한 작가의 체크포인트를 전진시키지만 간격 일정의 시간축은 바꾸지 않습니다.

자동 검사는 Pawchive의 UTC 의미를 가진 `added` 시간을 우선 사용하고 이전 성공 체크포인트에서 24시간을 겹쳐 확인합니다. 프로젝트 수준 중복 제거로 여러 계획이 같은 작품을 중복 집계하지 않습니다. 첫 무제한 실행은 기준만 만들고 전체 과거 작품을 새 항목으로 표시하지 않습니다. KToolBox가 중지된 동안 놓친 실행은 건너뛰며 같은 계획에 활성 작업이 있으면 중복 실행하지 않습니다. 자세한 내용은 [자동 동기화 가이드](../automatic-sync.md)를 참고하세요.

## 프로젝트 이름 형식

이름 설정과 기본 출력은 프로젝트 `ktoolbox.toml`에 저장되며 CLI, WebUI, MCP, 작품 다운로드와 자동 동기화가 함께 사용합니다. **이름 형식** 페이지는 구조와 템플릿을 각각 저장합니다. 재사용 가능한 이전 위치 변환기는 저장된 여러 형식이나 붙여 넣은 이전 `.env`/TOML을 원본으로 사용하고, 현재 프로젝트 형식을 읽기 전용 대상으로 유지하며 붙여 넣은 원문을 저장하지 않습니다. 사용자가 명시적으로 선택한 위치만 Pawchive 연결 없이 스캔하고 일시 중지, 계속 및 롤백을 지원합니다. 이전 위치는 이후 작업의 저장 대상이 아닙니다. 상속 규칙, 이전 설정 마이그레이션 마법사와 복구는 [이름 형식 가이드](../naming.md)를 참조하세요.

## 설정 편집

양식 레이블과 설명은 Python 식별자가 아닌 명시적으로 현지화된 텍스트입니다. 영어 설정 클래스의 `:ivar field:` docstring은 계속 필드 의미의 기준이며, 완전성 검사를 거친 언어 카탈로그가 7개 언어의 모든 레이블과 설명을 제공합니다. 형식, 기본값, 범위 및 비밀 메타데이터는 Pydantic이 제공합니다.

로그 수준 같은 고정 선택지는 아이콘이 있는 HeroUI Select를 사용하고, 추천값이 있지만 사용자 지정 입력도 허용하는 필드는 ComboBox를 사용합니다. `attachments`, `content.txt`, `external_links.txt` 같은 작품 내부 이름은 일반 텍스트 필드로 유지하며 실제 파일 시스템 위치에만 경로 선택기를 제공합니다.

`.env`와 `prod.env` 탭은 최종 유효 값과 출처 Chip을 표시합니다. 프로세스 환경에서 재정의된 값은 읽기 전용입니다. 비밀 값은 기본적으로 마스킹됩니다. 고급 텍스트 편집은 비밀을 노출할 수 있어 추가 경고를 표시합니다.

저장 전에 서버는 제안 파일을 파싱하고 검증하여 의미적 차이를 반환합니다. ETag로 오래된 편집을 거부하고 파일을 원자적으로 교체합니다. TOML 편집기는 기존 TomlKit/Pydantic 저장소를 사용하므로 구조화된 목록과 제외 규칙을 바꾼 후에도 주석이 유지됩니다.
