# 이름 형식

KToolBox v1의 이름 설정은 프로젝트별로 관리됩니다. CLI와 WebUI는 `ktoolbox.toml`의 같은 `[naming]` 섹션을 사용하며, 이름 필드는 더 이상 전역 dotenv 설정에서 편집하지 않습니다.

## 디렉터리 구조 설정

WebUI의 **이름 형식** 페이지에서 다음을 설정할 수 있습니다.

- 하나 이상의 다운로드 루트
- 크리에이터, 작품, 리비전, 연도 및 월 디렉터리 템플릿
- 기본 파일과 첨부 파일 템플릿
- 작품 내부의 첨부, 리비전, 본문 및 외부 링크 이름
- 연/월 그룹, 작품 파일 혼합 및 첨부 순차 이름

템플릿에는 필드 옆에 표시되는 `{creator_name}`, `{creator_id}`, `{service}`, `{title}`, `{post_id}`, `{revision_id}`, `{year}`, `{month}` 같은 변수만 사용할 수 있습니다. 경로 구분자, 상위 경로 이동, 알 수 없는 변수 및 안전하지 않은 이름은 스캔 전에 거부됩니다.

![어두운 테마의 이름 템플릿](../assets/webui/34-naming-templates-desktop-dark.png)

## 기존 다운로드 미리보기

**스캔 및 검토**는 실제 다운로드 루트를 스캔합니다. 작업 기록에 의존하지 않고 Pawchive에도 연결하지 않습니다. 크리에이터 디렉터리 신원, `creator-indices.ktoolbox`, `post.json`을 사용하며 루트 밖으로 나가는 심볼릭 링크를 따르지 않습니다.

미리보기에는 크리에이터별 이전/새 경로, 작품 수, 파일 수, 전체 크기, 건너뜀 및 충돌이 표시됩니다. **다운로드한 크리에이터 변환**은 기본으로 켜져 있고 안전하게 변환 가능한 크리에이터가 모두 선택됩니다.

![모바일 이름 변환 미리보기](../assets/webui/35-naming-conversion-mobile-light.png)

KToolBox는 대상을 덮어쓰거나 합치지 않습니다. 오래된 미리보기, 설정 변경, 관련 활성 작업, 중복 대상 또는 파일 시스템 변경이 있으면 다시 스캔해야 합니다.

## 적용 및 복구

변환을 켜면 KToolBox가 대기 설정 스냅샷을 저장한 뒤 백그라운드에서 이동합니다. 선택한 작업이 모두 성공한 후에만 새 설정을 활성화합니다. 취소, 쓰기 실패 또는 프로세스 중단 시 완료된 이동을 역순으로 되돌리고 이전 설정을 유지합니다.

진행률과 기록은 `.ktoolbox/webui.sqlite3`에 저장됩니다. 성공하면 임시 작업 로그를 지우고 기록은 수동 삭제할 때까지 보존합니다. 비어 있는 이전 디렉터리는 제거하지만 관련 없는 파일은 삭제하지 않습니다.

변환을 끄면 새 형식만 저장합니다. 기존 다운로드는 그대로 유지되고 이후 CLI와 WebUI 다운로드가 새 프로젝트 형식을 사용합니다.

## 최초 시작 마이그레이션

WebUI 최초 시작 시 기본 프로젝트 설정을 만들기 전에 `.env`와 `prod.env`의 이전 이름 키를 마이그레이션합니다.

1. 유효 값을 `ktoolbox.toml`에 기록
2. `.ktoolbox/migrations/project-naming-v2/`에 백업
3. 이전 dotenv 키 제거
4. 터미널 요약 출력
5. 로그인 후 한 번만 WebUI 알림 표시

![일회성 이름 마이그레이션 알림](../assets/webui/36-naming-migration-notice-light.png)

CLI도 프로젝트 이름 설정을 사용합니다. 이전 프로젝트는 WebUI를 한 번 시작해 백업과 원자적 마이그레이션을 완료하세요.
