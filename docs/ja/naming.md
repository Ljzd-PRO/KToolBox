# 命名形式

KToolBox v1 の命名設定はプロジェクト単位です。CLI と WebUI は `ktoolbox.toml` の同じ `[naming]` を使用し、命名項目はグローバル dotenv 設定では編集しません。

## ディレクトリ構造を設定する

WebUI の**命名形式**では、次を設定できます。

- 1 つ以上のダウンロードルート
- 作者、作品、リビジョン、年、月のディレクトリテンプレート
- メインファイルと添付ファイルのテンプレート
- 作品内の添付、リビジョン、本文、外部リンク名
- 年月グループ、作品ファイルの混在、添付の連番

テンプレートでは、欄の横に表示される `{creator_name}`、`{creator_id}`、`{service}`、`{title}`、`{post_id}`、`{revision_id}`、`{year}`、`{month}` などの変数だけを使用できます。パス区切り、親移動、未知の変数、安全でない名前はスキャン前に拒否されます。

![ダークテーマの命名テンプレート](../assets/webui/34-naming-templates-desktop-dark.png)

## 既存ダウンロードをプレビューする

**スキャンして確認**は実際のダウンロードルートを読み取ります。タスク履歴には依存せず、Pawchive にも接続しません。作者ディレクトリの識別情報、`creator-indices.ktoolbox`、`post.json` を使い、ルート外へ出るシンボリックリンクはたどりません。

プレビューには作者ごとの新旧パス、作品数、ファイル数、合計サイズ、スキップ、競合が表示されます。**ダウンロード済み作者を変換**は既定で有効で、安全に変換できる作者はすべて選択されます。

![モバイルの命名変換プレビュー](../assets/webui/35-naming-conversion-mobile-light.png)

KToolBox は対象を上書きまたは統合しません。古いプレビュー、設定変更、関連する実行中タスク、重複対象、ファイルシステム変更がある場合は再スキャンが必要です。

## 適用と復旧

変換を有効にすると、KToolBox は保留設定のスナップショットを保存し、バックグラウンド処理で移動します。選択した操作がすべて成功した場合だけ新設定を有効にします。取消、書き込み失敗、プロセス中断では完了済みの移動を逆順に戻し、旧設定を維持します。

進捗と履歴は `.ktoolbox/webui.sqlite3` に保存されます。成功時は一時操作ログを削除し、履歴は手動削除まで保持します。空になった移動元ディレクトリは削除しますが、無関係なファイルは削除しません。

変換を無効にした場合は新形式だけを保存します。既存ダウンロードは移動せず、以後の CLI と WebUI が新しい形式を使います。

## 初回起動時の移行

初回 WebUI 起動では、既定プロジェクト設定を作る前に `.env` と `prod.env` の旧命名キーを移行します。

1. 有効値を `ktoolbox.toml` に保存
2. `.ktoolbox/migrations/project-naming-v2/` にバックアップ
3. 旧 dotenv キーを削除
4. ターミナルに概要を表示
5. ログイン後に一度だけ通知

![一度だけ表示される命名移行通知](../assets/webui/36-naming-migration-notice-light.png)

CLI もプロジェクト命名設定を使用します。旧プロジェクトでは WebUI を一度起動し、バックアップ付きの原子的な移行を完了してください。
