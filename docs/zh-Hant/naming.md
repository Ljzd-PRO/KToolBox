# 命名格式

KToolBox v1 的命名設定屬於目前專案。CLI 與 WebUI 共同讀取 `ktoolbox.toml` 中的 `[naming]`；命名欄位不再作為全域 dotenv 設定編輯。

## 設定目錄結構

在 WebUI 開啟**命名格式**，可設定：

- 作者、作品、修訂、年份和月份目錄範本；
- 主檔案（封面）與附件檔案範本；
- 作品內部的附件、修訂、正文與外部連結名稱；
- 年月分組、混合作品與附件順序命名。

附件順序命名預設開啟，因為 Pawchive 經常傳回難以閱讀的儲存檔名。只有原始檔名有意義且需要保留時才建議關閉。

範本只能使用欄位旁列出的變數 Chip，例如 `{creator_name}`、`{creator_id}`、`{service}`、`{title}`、`{post_id}`、`{revision_id}`、`{year}` 和 `{month}`。路徑分隔符號、父目錄跳轉、未知變數與不安全名稱會在掃描前被拒絕。

「目錄結構」與「命名範本」各自提供儲存按鈕。儲存後會立即影響未來下載；只儲存命名設定絕不會移動舊檔案。

「預設下載位置」同樣屬於專案設定，預設值為 `downloads`。相對路徑以專案根目錄解析，也可填入專案外的主機絕對路徑。建立工作時依序使用：工作明確輸出目錄、自動同步計畫明確輸出目錄、專案預設下載位置。建立後會固定解析出的絕對路徑，日後修改專案預設值不會移動既有工作。

## 轉換舊下載位置

只有以前下載的內容需要採用已儲存命名格式時，才需開啟獨立的「舊下載目錄轉換」分頁。加入一個或多個舊位置，再按「掃描舊下載位置」。這些位置只是轉換掃描來源，不是未來工作的下載目錄設定。

轉換器可隨時使用，並提供兩種來源模式。「專案歷程」可多選已儲存的命名版本，適合單一下載位置混有多代目錄結構的情況。「貼上設定」支援舊 `.env` 命名鍵、完整 `ktoolbox.toml`、單獨的 `[naming]` 表格或無表頭命名片段。具高亮顯示的編輯器提供範例與欄位層級錯誤定位；貼上的原文只在記憶體中解析，不會寫入瀏覽器儲存空間、記錄、事件或轉換歷程。兩種模式都固定以目前專案命名版本作為唯讀目標，絕不覆寫專案設定。

掃描直接讀取檔案系統，不只依賴工作歷程，也不會存取 Pawchive。KToolBox 透過作者目錄身分、`creator-indices.ktoolbox` 與 `post.json` 識別內容，並拒絕跟隨越出所選位置的符號連結。

預覽會顯示每位作者的新舊路徑、作品數、檔案數、總大小、略過項目和衝突。所有可安全轉換的作者預設選取，也可逐項取消。

![行動版命名轉換預覽](../assets/webui/38-naming-conversion-mobile-dark.png)

KToolBox 不會覆寫或合併目標目錄。掃描結果過期、設定變更、相關工作正在活動、目標重複或檔案系統變化時，都必須重新掃描。

## 轉換與復原

KToolBox 會以持久背景工作執行選取的移動。「暫停」會等待目前原子檔案操作完成並保留已移動內容；「繼續」前會重新驗證設定、檔案指紋、目標衝突與可用空間。「取消」則會反向復原已完成移動；寫入失敗或處理程序中斷也會安全復原。已儲存的命名格式繼續用於未來下載。

轉換進度與歷程儲存在 `.ktoolbox/webui.sqlite3`。成功後會清除暫存操作記錄；完成歷程會保留到使用者手動刪除。轉換會移除已空的舊來源目錄，但不會刪除無關檔案。

## 首次啟動遷移

只有偵測到 `.env` 或 `prod.env` 中存在舊命名鍵時才顯示遷移精靈。啟動階段只偵測並於終端機警告，不會預先修改檔案。登入後，精靈會：

1. 顯示每個來源、舊值與目前專案值；
2. 預設選取舊值，並允許逐項保留目前值；
3. 預覽將修改的專案設定與將移除的 dotenv 鍵；
4. 確認後備份至 `.ktoolbox/migrations/project-naming-v2/`，再原子寫入 `ktoolbox.toml` 並移除舊鍵；
5. 設定遷移成功後，再進入獨立的舊目錄轉換步驟。

![舊版命名設定遷移精靈](../assets/webui/39-naming-migration-desktop-light.png)

關閉或選擇「忽略」只會關閉本次視窗。只要舊鍵仍存在，重新整理或重新登入後仍會顯示。設定遷移與目錄轉換彼此獨立：設定完成後先確認一個或多個舊位置，再明確按下「掃描舊下載位置」；僅開啟工具不會自動掃描或移動檔案。

CLI 同樣使用專案命名設定。舊專案尚未完成遷移時，請啟動 WebUI 並確認具有備份的原子遷移。只存在於處理程序環境中的舊值無法由 KToolBox 刪除；專案命名會忽略它們，並持續警告使用者從啟動環境移除。
